# Finnish Grammar Content Creator

Use the Sisu Steps repository containing this skill. Resolve repository paths from this directory (`../../..`) rather than a personal installation or a machine-specific checkout.

## Read the repository contract

Read [root guidance](../../../AGENTS.md), the [constitution](../../../specs/constitution.md), the [content-authoring policy](../../../specs/content-authoring.md), and the active G001 [plan](../../../specs/features/G001-local-finnish-exercise-book/plan.md), [requirements](../../../specs/features/G001-local-finnish-exercise-book/requirements.md), and [validation](../../../specs/features/G001-local-finnish-exercise-book/validation.md) before content work. Follow the repository's authority order. The policy owns detailed content rules and assessment criteria; this skill owns the agent workflow.

Before editing content, inspect the current catalog, models, and validators and read the applicable client guidance identified in [repository integration](references/repository-contract.md). Read that reference when adding, integrating, or validating a pack; [learner-facing examples](references/learner-facing-content.md) when writing or auditing teaching, prompts, answers, or feedback; and the [assessment template](references/pedagogy-assessment.md) when recording a pedagogy gate.

## Author or revise a pack

1. Establish the topic boundary, starting and expected ending level, and the user's emphases and exclusions. For a systematic correction, inventory the complete affected class before editing. Before bulk wording changes, show one representative before/after example per issue category unless the user explicitly waived a preview.
2. Research authoritative Finnish sources and record them in the pack and assessment. Build the important-skill, prerequisite, misconception, and vocabulary map using the policy checkpoints below. Assess the blueprint before bulk question writing and save the actual pre-authoring decision with the assessment template.
3. Author lessons and exercises from the approved blueprint. Use the policy's independent question-word inventory and the learner-facing examples. For existing packs, identify compatibility consequences before editing and retain the approved content-preservation boundary.
4. Integrate and validate using the repository reference, current client guidance, and owning feature validation. Check authored sources, runtime validation, grading alternatives, and applicable rendered workflows at the boundaries required by the change.
5. Assess the finished rendered content against the complete final rubric. Record audited counts, exceptions, corrections, limitations, and the actual disposition. Resolve high-impact findings and failed technical checks before handoff.

## Audit and handoff

For an audit, apply the same policy to the complete requested scope and report findings and evidence. Distinguish read-only findings from authorized corrections, and retain dated historical evidence.

At handoff, report the chosen question count, Focused coverage and Review boundary, both applicable assessment dispositions, inventory counts and exceptions, compatibility consequences, checks actually completed, and limitations. Documentation-only skill maintenance uses metadata, link, and formatting checks; content changes use the repository's content validation and rendered assessment workflow.
